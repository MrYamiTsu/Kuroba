Quickstart & Installation

Kuroba is fully self-contained with zero npm dependencies. A standard Node.js runtime (v16.0.0 or higher) is all that is required to execute scripts or run the interactive REPL shell.

Local Installation via Git

git clone https://github.com/MrYamiTsu/Kuroba.git
cd Kuroba

Kuroba source files use the conventional .krb extension. On Windows, you can also use the bundled convenience launcher .\krb.cmd main.krb.

CLI & Command-Line Arguments

Kuroba automatically parses and injects all trailing parameters into the global scope as an immutable List<String> accessible through args:

node index.js script.krb --host 127.0.0.1 --port 8080 --verbose

Processing Arguments in Kuroba

pasteLn("Arguments received: " + args.count());

for (i, param in args) then
    pasteLn("Arg #" + i + ": " + param);
end

if (args.count() > 0) then
    if (args[0] == "--help" || args[0] == "-h") then
        pasteLn("Displaying script manual...");
    end
end

Interactive REPL Shell (`krb`)

Invoking index.js or the launcher shortcut ./krb.cmd without arguments starts an interactive read-eval-print loop shell:

node index.js
# Or via Windows shortcut:
.\krb.cmd

Shell Features

  • Instant Expression Evaluation: Values like 42, "Kuroba", TRUE, and math expressions evaluate and display immediately.
  • Stateful Scope: Declared variables (ivar, iconst) and functions persist throughout the entire session.
  • Smart Multi-line Buffering: Writing open blocks (if ... then, function ... then, for ... then) switches the prompt to ... until closed by end.
  • Built-in Commands: help() for usage tips, clear() to clear the screen, and exit() (or Ctrl+C) to terminate cleanly.

Variables, Constants & Lifecycle

Kuroba enforces clear boundaries between mutable variables and immutable constants declared at initialization:

Variable Declaration (ivar)

Declares a variable whose initial type is inferred from the assigned expression:

ivar score = 100;       ~~ Inferred as Int
ivar hero = "Shinobi";  ~~ Inferred as String
ivar ratio = 3.14;      ~~ Inferred as Float
ivar active = TRUE;     ~~ Inferred as Bool
score += 25;            ~~ Reassignment allowed

Constant Declaration (iconst)

Declares an immutable constant. Any attempt to reassign, retype, or destroy a constant triggers an immediate runtime [TypeError]:

iconst PI = 3.141592653589793;
iconst PORT = 8080;
PORT = 3000; ~~ [TypeError] Cannot reassign constant 'PORT'.

Variable Destruction (kill)

The kill statement explicitly purges a variable from memory and active scope. Constants cannot be killed. If an inner shadowed variable is killed, the outer variable becomes visible again:

ivar buffer = [1, 2, 3, 4, 5];
pasteLn(buffer.count()); ~~ 5

kill buffer;             ~~ Releases variable and frees its scope entry
pasteLn(buffer);         ~~ [ReferenceError] Variable 'buffer' is not defined.

Type System & Non-Nullability

Kuroba balances dynamic ergonomics with static-grade runtime safety contracts.

Type Kind Example Literal Description
Int Primitive 42, -10 64-bit integer numbers
Float Primitive 3.14159, -0.05 Floating-point numbers
String Primitive "Kuroba", "" UTF-8 text strings
Bool Primitive TRUE, FALSE Boolean truth values (1 == TRUE, 0 == FALSE)
NULL Primitive NULL Intentional absence of a value
List<T> Compound [1, 2, 3] Dynamic, 0-indexed ordered array
Stack<T> Compound [10, 20] LIFO (Last In, First Out) stack
Queue<T> Compound ["A", "B"] FIFO (First In, First Out) queue
Table Compound { name: "Kuroba", hp: 100 } Key-value associative dictionary with typed fields
Function First-Class function f(...) then ... end Named or anonymous callable closure

Explicit Type Coercion (~Type)

Appending ~Type to ivar converts the right-hand value immediately:

ivar~Int counter = "42";   ~~ Coerced to Int 42
ivar~String port = 8080;   ~~ Coerced to String "8080"
ivar~Bool active = 1;      ~~ Coerced to TRUE (0 becomes FALSE)
ivar~Float ratio = "3.14"; ~~ Coerced to Float 3.14

Strict Non-Nullable Contract (~(Type))

Guarantees that a variable or field can never receive NULL, raising an immediate [TypeError] upon violation:

ivar~(String) user = "Admin";
user = NULL; ~~ [TypeError] Cannot assign NULL to non-nullable variable 'user'.

Dynamic In-Place Retyping

An existing variable can change type dynamically during assignment using var~Type = val;:

ivar score = 100;           ~~ Inferred as Int
score~String = "Top Score"; ~~ Retyped to String in-place
score~Float = 99.5;         ~~ Retyped to Float in-place

Operators & Precedence Table

Kuroba evaluates expressions following standard mathematical precedence rules:

Level Category Operator Description Associativity
1 Primary (...), [], ., () Grouping, indexing, member access, function calls Left-to-right
2 Unary !, ++, --, - Logical NOT, postfix step increment/decrement, negation Right-to-left
3 Multiplicative *, /, % Multiplication, division, modulo (0-check enforced) Left-to-right
4 Additive +, - Addition, string concatenation, subtraction Left-to-right
5 Relational <, >, <=, >= Numeric and comparative order checks Left-to-right
6 Equality ==, != Strict equality with boolean/NULL coercion Left-to-right
7 Logical AND && Short-circuit boolean AND Left-to-right
8 Logical OR || Short-circuit boolean OR Left-to-right
9 Native Swap <-> Atomic in-place variable swap Non-associative
10 Assignment =, +=, -=, *=, /=, %= Variable assignment and compound updates Right-to-left

Native Atomic Swap (<->)

Exchanges the values of two variables in-place without a temporary holder. It validates type compatibility, guards constants, and prevents transferring NULL into a non-nullable variable:

ivar a = 10;
ivar b = 99;
a <-> b;
pasteLn(a); ~~ 99
pasteLn(b); ~~ 10

String Interpolation (~"...")

The raven tilde prefix allows embedded Kuroba expressions between curly braces:

ivar hero = "Kenji";
ivar hp = 85;
pasteLn(~"Hero: {hero} | Health: {hp}/100 | Boosted: {hp + 15}");

Control Flow & Pattern Matching

Block statements conclude explicitly with the end keyword and do not require a trailing semicolon.

Conditionals (if / elif / else / end)

ivar score = 75;

if (score == 100) then
    pasteLn("Perfect score!");
elif (score >= 75) then
    pasteLn("Good job!");
else
    pasteLn("Try again.");
end

ivar running = TRUE;
if running then ~~ Single variable checks do not require parentheses
    pasteLn("System operational.");
end

Pattern Matching & Redirect Rule (given / case ... then / end)

Branch selector matching a target value against case ... then options. Kuroba implements a unique Redirect Rule: if break; is omitted, execution does not bleed into subsequent cases — it redirects straight to the default case ~ then fallback branch:

ivar role = "admin";

given role then
    case "user" then
        pasteLn("Standard user dashboard");
        break;
    case "admin" then
        pasteLn("Full administrative privileges");
        break;
    case ~ then
        pasteLn("Unknown role; access restricted.");
end

Loops: for, while, do-while

~~ 1. Standard 3-clause for loop (break; and skip; supported)
for (ivar i = 0; i < 5; i++) then
    if (i == 2) then skip; end
    pasteLn(i);
end

~~ 2. While loop
ivar count = 0;
while (count < 3) then
    pasteLn(count);
    count++;
end

~~ 3. Do-While loop (guaranteed at least one execution)
ivar n = 0;
do
    pasteLn(n);
    n++;
while (n < 3);

Collection Iteration (for ... in)

ivar~List fruits = ["apple", "banana", "cherry"];
for (fruit in fruits) then
    pasteLn(fruit);
end

ivar~Table hero = { name: "Kenji", class: "Shinobi" };
for (key, val in hero) then
    pasteLn(key + " => " + val);
end

Inline Guards & Termination (exit)

exit();          ~~ Exits immediately with code 0
exit(score < 0); ~~ Inline guard clause: exits only if condition evaluates to true

Exceptions & Error Handling (throw, try / catch)

The throw <expression>; statement halts execution immediately, displays a distinct vermilion / orange-red diagnostic (ANSI \x1b[38;2;255;85;0m / #FF5500), and exits the process with status code 1 when uncaught. To safely intercept errors at runtime, Kuroba provides the try ... catch (ivar e) ... finally ... end construct.

1. Throwing Primitives & Values

Any Kuroba expression can be thrown directly:

~~ Throwing a String
throw "Invalid user credentials";
~~ Output: [Exception: Line 2, Col 1] Invalid user credentials

~~ Throwing an HTTP status code
throw 404;
~~ Output: [Exception: Line 6, Col 1] 404

2. Structured Exception Tables

When throwing a Table, Kuroba recognizes special metadata fields to format the diagnostic output with precision:

Field Type Default Behavior
exName String "Exception" Replaces the bracketed header name (e.g. [AuthError] instead of [Exception]).
exLines Bool TRUE When FALSE, suppresses line and column numbers from the header.
exCode Int / String NULL Prefixes the diagnostic message with Error <exCode>: .
exContext String NULL Sets the error description body, replacing default table serialization.
exTime Bool FALSE When TRUE, prepends the local timestamp ([YYYY-MM-DD HH:MM:SS]) at the start of the error line.

Examples of Structured Exceptions

~~ Custom name, HTTP code, description, and timestamp
throw {
    exName: "AccessDenied",
    exCode: 403,
    exTime: TRUE,
    exContext: "Root privileges required for this operation"
};
~~ Output: [2026-11-10 13:22:09] [AccessDenied: Line 2, Col 1] Error 403: Root privileges required for this operation

~~ Suppressing line tracking for clean CLI alerts
throw {
    exName: "SecurityPanic",
    exLines: FALSE,
    exContext: "Immediate intrusion alert detected"
};
~~ Output: [SecurityPanic] Immediate intrusion alert detected

~~ Code without context (formats the table data)
throw { exCode: 404, route: "/api/v1/users" };
~~ Output: [Exception: Line 13, Col 1] Error 404: { route: "/api/v1/users", exCode: 404 }

3. Exception Handling (try ... catch (ivar e) ... finally ... end)

The try block wraps guarded operations. The trailing then keyword is optional across all clauses (try or try then, catch (ivar e) or catch (ivar e) then, finally or finally then):

try
    pasteLn("1. Attempting secure transaction...");
    throw {
        exName: "PaymentError",
        exContext: "Insufficient account balance"
    };
catch (ivar err) then
    pasteLn("2. Caught exception: " + err.exName);
    pasteLn("   Reason: " + err.exContext);
finally
    pasteLn("3. Transaction session closed.");
end

4. Intercepting Native Runtime Errors

Kuroba's try / catch seamlessly captures built-in runtime failures (such as division by zero, missing files, or out-of-bounds indexing) and transforms them into structured tables with exName and exContext fields:

try
    ~~ Trigger a division by zero error
    ivar result = 100 / 0;
catch (ivar e) then
    pasteLn("Error intercepted: " + e.exName);
    pasteLn("Details: " + e.exContext);
end
~~ Output:
~~ Error intercepted: MathError
~~ Details: Division by zero is undefined.

Console I/O & Interactive Input

Kuroba provides synchronous primitives for building responsive terminal applications and CLI tools.

Output: paste & pasteLn

paste("Loading: ");
paste("50%...");
pasteLn(" Done!");
pasteLn(); ~~ Prints an empty line

Line Input: copy(...)

Blocks execution synchronously and reads an entire line of text until the user presses Enter:

ivar username = copy("Enter your name: ");
pasteLn("Greetings, " + username);

ivar~Int age = copy("Your age: ");
pasteLn("Next year: " + (age + 1));

Single Keypress: copyKey()

Captures a single keypress immediately in raw terminal mode without waiting for the Enter key. Pressing Ctrl+C cleanly exits:

paste("Proceed with update? (y/n): ");
ivar key = copyKey();
pasteLn("");

if (key == "y" || key == "Y") then
    pasteLn("Update starting...");
end

Screen Management: clear

clear();            ~~ Clears the terminal screen immediately
clear(round > 1);   ~~ Clears screen only if condition is true

Typed Collections (List, Stack, Queue, Table)

Kuroba offers four built-in high-performance data structures:

1. Lists (List<T>)

Dynamic 0-indexed arrays supporting generic typing, nullability contracts, and methods:

ivar~List numbers = [10, 30];
numbers.push(20, 1);      ~~ Inserts 20 at index 1 -> [10, 20, 30]
pasteLn(numbers.peek(1)); ~~ 20 (inspects element at index 1)
pasteLn(numbers.pop(0));  ~~ 10 (removes and returns element at index 0)
pasteLn(numbers.count()); ~~ 2

Generic Typing & Nullability Matrix

Syntax List Nullable? Elements Nullable? Description
ivar~List<Type> Yes Yes Nullable list; elements can be Type or NULL.
ivar~List<(Type)> Yes No Nullable list; elements must strictly be non-null Type.
ivar~(List<Type>) No No Non-nullable list and non-nullable elements.

2. Stacks (Stack<T> — LIFO)

ivar~Stack stack = [10, 20];
stack.push(30);         ~~ Pushes to top: [10, 20, 30]
pasteLn(stack.peek());  ~~ 30 (inspects top without removing)
pasteLn(stack.pop());   ~~ 30 (removes and returns top)
pasteLn(stack.count()); ~~ 2

3. Queues (Queue<T> — FIFO)

ivar~Queue clients = ["Alice", "Bob"];
clients.push("Charlie");   ~~ Adds to back
pasteLn(clients.peek());   ~~ "Alice" (inspects front without removing)
pasteLn(clients.pop());    ~~ "Alice" (removes and returns front)
pasteLn(clients.count());  ~~ 2

4. Tables (Table)

Key-value associative maps accessed exclusively through dot notation (table.field). Reading an undefined field returns NULL:

ivar~Table hero = {
    name: "Kuroba",
    hp: 100,
    port~Int: "8080",          ~~ Field-level type coercion
    token~(String): "xyz123"   ~~ Field-level strict non-nullability
};

hero.hp -= 15;                 ~~ In-place update
hero.level = 5;                ~~ Dynamically creates field 'level'
pasteLn(hero.missingProp);     ~~ NULL (safe access)

Functions & Native Hooks

Named Functions & Signatures

Named functions declare parameters prefixed by ivar with optional type coercion (ivar~Int x) and non-nullability constraints (ivar~(String) name):

function calculateDamage(ivar base, ivar~Int multiplier) then
    return base * multiplier;
end

pasteLn(calculateDamage(25, 2)); ~~ 50

Anonymous Lambdas (function ~) & Closures

function createMultiplier(ivar factor) then
    return function ~(ivar n) then
        return n * factor;
    end;
end

ivar triple = createMultiplier(3);
pasteLn(triple(10)); ~~ 30

Native Function Interception (Hooks)

The hook statement intercepts existing function calls (or Table methods) to inject telemetry, caching, or data validation without altering the caller interface. Inside the hook body, this(...) invokes the original function:

function processPayment(ivar amount, ivar fee) then
    return amount + fee;
end

~~ Interception hook
hook processPayment(ivar amount, ivar fee) then
    pasteLn(~"[AUDIT] Processing payment: {amount}$ (Fee: {fee}$)");
    ivar total = this(amount, fee);
    pasteLn(~"[AUDIT] Validation approved: Total = {total}$");
    return total;
end

ivar invoice = processPayment(250, 15);

Namespaces & Module Discovery

Kuroba resolves modules purely from declared AST symbols, independent of physical file names on disk:

Hierarchy: Namespace → Module Slice (~Module) → Members

  • Main Namespace: Single entry point for applications. Strictly indivisible (cannot have ~Module) and cannot be imported by other files.
  • Library Namespaces: Declare reusable modules using namespace Lib ~Slice then ... end.
  • Symbol Discovery: Kuroba indexes files by declared symbols. Renaming math.krb to algorithms.krb does not break any imports.

Import Variations

~~ 1. Entire namespace
import Std;
pasteLn(Std.Math.PI);

~~ 2. Namespace alias
import Std alias S;
pasteLn(S.Math.PI);

~~ 3. Root exposure of entire namespace
import Std alias ~;
pasteLn(Math.PI);

~~ 4. Selective module slices into root scope
import Std ~(Math, Time, String, IO) alias ~;
pasteLn(Math.sqrt(16));

Error Diagnostics (All 6 Classes)

Kuroba provides exact line, column, and contextual diagnostics for rapid debugging:

1. SyntaxError

Grammar violations during tokenization or AST parsing:

[SyntaxError: Line 2, Col 1] Missing semicolon ';' at the end of statement.
[SyntaxError: Line 4, Col 12] Unclosed parenthesis. Missing closing ')' to match '(' at Line 4, Col 6.
[SyntaxError: Line 10, Col 5] Return statements are only allowed inside functions.

2. TypeError

Violations of runtime type compatibility or non-nullability contracts:

[TypeError] Cannot assign type 'String' to variable 'count' of type 'Int'.
[TypeError] Cannot reassign constant 'PORT'.
[TypeError] Cannot assign NULL to non-nullable variable 'user' of type '(String)'.
[TypeError] Cannot kill constant variable 'PI'.
[TypeError] Cannot hook non-function target 'score'.

3. ReferenceError

Referencing undeclared identifiers or out-of-scope hook contexts:

[ReferenceError] Variable 'unknown' is not defined.
[ReferenceError] Cannot call 'this()' outside of a hook interception.
[ReferenceError] Cannot kill undefined variable 'temp'.

4. MathError

Undefined mathematical calculations:

[MathError] Division by zero is undefined.
[MathError] Modulo by zero is undefined.

5. IndexError

Accessing out-of-bounds indices or non-integer collection lookups:

[IndexError] Index 5 out of bounds for list of length 2.
[IndexError] List index must be an integer, got 'abc'.

6. IOError

Filesystem access or permission failures in Std.IO:

[IOError] File not found: 'missing_save.dat'.
[IOError] Failed to write to file 'protected/root.dat': EACCES: permission denied.
