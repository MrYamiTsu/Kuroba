Setup & CLI Chapter 1 of 15

Quickstart & Installation

Kuroba is fully self-contained with zero npm dependencies. A standard Node.js runtime (v16.0.0 or higher) is all that is required to execute scripts or run the interactive REPL shell.

Local Installation via Git

git clone https://github.com/MrYamiTsu/Kuroba.git
cd Kuroba

Kuroba source files use the conventional .krb extension. On Windows, you can also use the bundled convenience launcher .\krb.cmd main.krb.

CLI & Command-Line Arguments

Kuroba automatically parses and injects all trailing parameters into the global scope as an immutable List<String> accessible through args:

node index.js script.krb --host 127.0.0.1 --port 8080 --verbose

Processing Arguments in Kuroba

pasteLn("Arguments received: " + args.count());

for (ivar i, param in args) then
    pasteLn("Arg #" + i + ": " + param);
end

if (args.count() > 0) then
    if (args[0] == "--help" || args[0] == "-h") then
        pasteLn("Displaying script manual...");
    end
end

Interactive REPL Shell (krb)

Invoking index.js or the launcher shortcut ./krb.cmd without arguments starts an interactive read-eval-print loop shell:

node index.js
# Or via Windows shortcut:
.\krb.cmd

Shell Features

  • Instant Expression Evaluation: Values like 42, "Kuroba", TRUE, and math expressions evaluate and display immediately.
  • Stateful Scope: Declared variables (ivar, iconst) and functions persist throughout the entire session.
  • Smart Multi-line Buffering: Writing open blocks (if ... then, function ... then, for ... then) switches the prompt to ... until closed by end.
  • Built-in Commands: help() for usage tips, clear() to clear the screen, and exit() (or Ctrl+C) to terminate cleanly.

Variables, Constants & Lifecycle

Kuroba enforces clear boundaries between mutable variables and immutable constants declared at initialization:

Variable Declaration (ivar)

Declares a variable whose initial type is inferred from the assigned expression:

ivar score = 100;       ~~ Inferred as Int
ivar hero = "Shinobi";  ~~ Inferred as String
ivar ratio = 3.14;      ~~ Inferred as Float
ivar active = TRUE;     ~~ Inferred as Bool
score += 25;            ~~ Reassignment allowed

Multi-Variable Declarations & Propagation

Declare multiple variables on a single line. If fewer values than variables are provided, the trailing expression is re-evaluated cleanly for every remaining variable (and any global ~Type applies to all of them):

ivar a, b = 1, 2;          ~~ a = 1, b = 2
ivar c, d = 4;             ~~ c = 4, d = 4
ivar e, f, g = 2, 5;       ~~ e = 2, f = 5, g = 5
ivar~Int x, y = "10", 20;  ~~ x = 10, y = 20 (both cast to Int)

Constant Declaration (iconst)

Declares an immutable constant. Any attempt to reassign, retype, or destroy a constant triggers an immediate runtime [TypeError]:

iconst PI = 3.141592653589793;
iconst PORT = 8080;
PORT = 3000; ~~ [TypeError] Cannot reassign constant 'PORT'.

Variable Destruction (kill)

The kill statement explicitly purges a variable from memory and active scope. Constants cannot be killed. If an inner shadowed variable is killed, the outer variable becomes visible again:

ivar buffer = [1, 2, 3, 4, 5];
pasteLn(buffer.count()); ~~ 5

kill buffer;             ~~ Releases variable and frees its scope entry
pasteLn(buffer);         ~~ [ReferenceError] Variable 'buffer' is not defined.

Type System & Non-Nullability

Kuroba balances dynamic ergonomics with static-grade runtime safety contracts.

Type Kind Example Literal Description
Int Primitive 42, -10 64-bit integer numbers
Float Primitive 3.14159, -0.05 Floating-point numbers
String Primitive "Kuroba", "" UTF-8 text strings
Bool Primitive TRUE, FALSE Boolean truth values (1 == TRUE, 0 == FALSE)
NULL Primitive NULL Intentional absence of a value
List<T> Compound [1, 2, 3] Dynamic, 0-indexed ordered array
Stack<T> Compound [10, 20] LIFO (Last In, First Out) stack
Queue<T> Compound ["A", "B"] FIFO (First In, First Out) queue
Table Compound { name: "Kuroba", hp: 100 } Key-value associative dictionary with typed fields
Function First-Class function f(...) then ... end Named or anonymous callable closure

Explicit Type Coercion (~Type)

Appending ~Type to ivar converts the right-hand value immediately:

ivar~Int counter = "42";   ~~ Coerced to Int 42
ivar~String port = 8080;   ~~ Coerced to String "8080"
ivar~Bool active = 1;      ~~ Coerced to TRUE (0 becomes FALSE)
ivar~Float ratio = "3.14"; ~~ Coerced to Float 3.14

Strict Non-Nullable Contract (~(Type))

Guarantees that a variable or field can never receive NULL, raising an immediate [TypeError] upon violation:

ivar~(String) user = "Admin";
user = NULL; ~~ [TypeError] Cannot assign NULL to non-nullable variable 'user'.

Dynamic In-Place Retyping

An existing variable can change type dynamically during assignment using var~Type = val;:

ivar score = 100;           ~~ Inferred as Int
score~String = "Top Score"; ~~ Retyped to String in-place
score~Float = 99.5;         ~~ Retyped to Float in-place

Runtime Type Checking (is)

The is operator evaluates to a strict boolean verifying whether a value matches a native type (Int, Float, String, Bool, List, Stack, Queue, Table, Function), a strict literal (NULL, TRUE, FALSE), or a typed generic collection (List<Int>, List<(Int)>, Stack<String>). Unknown types raise an immediate [TypeError]:

ivar items = [10, 20, 30];
pasteLn(items is List);      ~~ TRUE
pasteLn(items is List<Int>); ~~ TRUE
pasteLn(1 is TRUE);          ~~ FALSE (strict boolean identity)
pasteLn(!(5 is String));     ~~ TRUE

Operators & Precedence Table

Kuroba evaluates expressions following standard mathematical precedence rules:

Level Category Operator Description Associativity
1 Primary (...), [], ., () Grouping, indexing, member access, function calls Left-to-right
2 Unary !, ++, --, - Logical NOT, postfix step increment/decrement, negation Right-to-left
3 Multiplicative *, /, % Multiplication, division, modulo (0-check enforced) Left-to-right
4 Additive +, - Addition, string concatenation, subtraction Left-to-right
5 Relational <, >, <=, >=, is Numeric/comparative order and runtime type checks Left-to-right
6 Equality ==, != Strict equality with boolean/NULL coercion Left-to-right
7 Logical AND && Short-circuit boolean AND Left-to-right
8 Logical OR || Short-circuit boolean OR Left-to-right
9 Native Swap <-> Atomic in-place variable swap Non-associative
10 Assignment =, +=, -=, *=, /=, %= Variable assignment and compound updates Right-to-left

Native Atomic Swap (<->)

Exchanges the values of two variables, list elements, or table fields in-place without a temporary holder. It validates type compatibility, guards constants, and prevents transferring NULL into a non-nullable variable:

ivar a = 10;
ivar b = 99;
a <-> b;
pasteLn(a); ~~ 99
pasteLn(b); ~~ 10

~~ In-place list elements swap (ideal for shuffle / sorting)
ivar deck = [1, 2, 3];
deck[0] <-> deck[2];
pasteLn(deck); ~~ [3, 2, 1]

~~ Table properties swap
ivar hero = { main: "Sword", stash: "Bow" };
hero.main <-> hero.stash;
pasteLn(hero.main); ~~ "Bow"

String Interpolation (~"...")

The tilde prefix allows embedded Kuroba expressions between curly braces:

ivar hero = "Kenji";
ivar hp = 85;
pasteLn(~"Hero: {hero} | Health: {hp}/100 | Boosted: {hp + 15}");

Control Flow & Pattern Matching

Block statements conclude explicitly with the end keyword and do not require a trailing semicolon.

Conditionals (if / elif / else / end)

ivar score = 75;

if (score == 100) then
    pasteLn("Perfect score!");
elif (score >= 75) then
    pasteLn("Good job!");
else
    pasteLn("Try again.");
end

ivar running = TRUE;
if running then ~~ Single variable checks do not require parentheses
    pasteLn("System operational.");
end

Pattern Matching & Redirect Rule (given / case ... then / end)

Branch selector matching a target value against case ... then options. Kuroba implements a unique Redirect Rule: if break; is omitted, execution does not bleed into subsequent cases — it redirects straight to the default case ~ then fallback branch:

ivar role = "admin";

given role then
    case "user" then
        pasteLn("Standard user dashboard");
        break;
    case "admin" then
        pasteLn("Full administrative privileges");
        break;
    case ~ then
        pasteLn("Unknown role; access restricted.");
end

Loops: for, while, do-while

~~ 1. Standard 3-clause for loop (break; and skip; supported)
for (ivar i = 0; i < 5; i++) then
    if (i == 2) then skip; end
    pasteLn(i);
end

~~ 2. While loop
ivar count = 0;
while (count < 3) then
    pasteLn(count);
    count++;
end

~~ 3. Do-While loop (guaranteed at least one execution, optional 'then')
ivar n = 0;
do then
    pasteLn(n);
    n++;
while (n < 3);

Collection Iteration (for ... in)

ivar~List<String> fruits = ["apple", "banana", "cherry"];
for (ivar fruit in fruits) then
    pasteLn(fruit);
end

ivar~Table hero = { name: "Kenji", class: "Shinobi" };
for (ivar key, val in hero) then
    pasteLn(key + " => " + val);
end

Inline Guards & Termination (exit)

exit();          ~~ Exits immediately with code 0
exit(score < 0); ~~ Inline guard clause: exits only if condition evaluates to true

Exceptions & Error Handling (throw, try / catch)

The throw <expression>; statement halts execution immediately, displays a distinct vermilion / orange-red diagnostic (ANSI \x1b[38;2;255;85;0m / #FF5500), and exits the process with status code 1 when uncaught. To safely intercept errors at runtime, Kuroba provides the try ... catch (ivar e) ... finally ... end construct.

1. Throwing Primitives & Values

Any Kuroba expression can be thrown directly:

~~ Throwing a String
throw "Invalid user credentials";
~~ Output: [Exception: Line 2, Col 1] Invalid user credentials

~~ Throwing an HTTP status code
throw 404;
~~ Output: [Exception: Line 6, Col 1] 404

2. Structured Exception Tables

When throwing a Table, Kuroba recognizes special metadata fields to format the diagnostic output with precision:

Field Type Default Behavior
eName String "Exception" Replaces the bracketed header name (e.g. [AuthError] instead of [Exception]).
eLines Bool TRUE When FALSE, suppresses line and column numbers from the header.
eCode Int / String NULL Prefixes the diagnostic message with Error <eCode>: .
eContext String NULL Sets the error description body, replacing default table serialization.
eTime Bool FALSE When TRUE, prepends the local timestamp ([YYYY-MM-DD HH:MM:SS]) at the start of the error line.
eLine / eCol Int NULL Line and column metadata attached when intercepting errors or inspecting diagnostics.

Examples of Structured Exceptions

~~ Custom name, HTTP code, description, and timestamp
throw {
    eName: "AccessDenied",
    eCode: 403,
    eTime: TRUE,
    eContext: "Root privileges required for this operation"
};
~~ Output: [2026-11-10 13:22:09] [AccessDenied: Line 2, Col 1] Error 403: Root privileges required for this operation

~~ Suppressing line tracking for clean CLI alerts
throw {
    eName: "SecurityPanic",
    eLines: FALSE,
    eContext: "Immediate intrusion alert detected"
};
~~ Output: [SecurityPanic] Immediate intrusion alert detected

~~ Code without context (formats the table data)
throw { eCode: 404, route: "/api/v1/users" };
~~ Output: [Exception: Line 13, Col 1] Error 404: { route: "/api/v1/users", eCode: 404 }

3. Exception Handling (try ... catch (ivar e) ... finally ... end)

The try block wraps guarded operations. The trailing then keyword is optional across all clauses (try or try then, catch (ivar e) or catch (ivar e) then, finally or finally then):

try
    pasteLn("1. Attempting secure transaction...");
    throw {
        eName: "PaymentError",
        eContext: "Insufficient account balance"
    };
catch (ivar err) then
    pasteLn("2. Caught exception: " + err.eName);
    pasteLn("   Reason: " + err.eContext);
finally
    pasteLn("3. Transaction session closed.");
end

4. Intercepting Native Runtime Errors

Kuroba's try / catch seamlessly captures built-in runtime failures (such as division by zero, missing files, or out-of-bounds indexing) and transforms them into structured tables with eName, eContext, and eLine fields:

try
    ~~ Trigger a division by zero error
    ivar result = 100 / 0;
catch (ivar e) then
    pasteLn("Error intercepted: " + e.eName);
    pasteLn("Details: " + e.eContext);
end
~~ Output:
~~ Error intercepted: MathError
~~ Details: Division by zero is undefined.

Console I/O & Interactive Input

Kuroba provides synchronous primitives for building responsive terminal applications and CLI tools.

Output: paste & pasteLn

paste("Loading: ");
paste("50%...");
pasteLn(" Done!");
pasteLn(); ~~ Prints an empty line

Line Input: copy(...)

Blocks execution synchronously and reads an entire line of text until the user presses Enter:

ivar username = copy("Enter your name: ");
pasteLn("Greetings, " + username);

ivar~Int age = copy("Your age: ");
pasteLn("Next year: " + (age + 1));

Single Keypress: copyKey()

Captures a single keypress immediately in raw terminal mode without waiting for the Enter key. Pressing Ctrl+C cleanly exits:

paste("Proceed with update? (y/n): ");
ivar key = copyKey();
pasteLn("");

if (key == "y" || key == "Y") then
    pasteLn("Update starting...");
end

Screen Management: clear

clear();            ~~ Clears the terminal screen immediately
clear(round > 1);   ~~ Clears screen only if condition is true

Typed Collections (List, Stack, Queue, Table)

Kuroba offers four built-in high-performance data structures:

1. Lists (List<T>)

Dynamic 0-indexed arrays supporting generic typing, nullability contracts, and methods:

ivar~List<Int> numbers = [10, 30];
numbers.push(20, 1);      ~~ Inserts 20 at index 1 -> [10, 20, 30]
pasteLn(numbers.peek(1)); ~~ 20 (inspects element at index 1)
pasteLn(numbers.pop(0));  ~~ 10 (removes and returns element at index 0)
pasteLn(numbers.count()); ~~ 2

Generic Typing & Nullability Matrix

Syntax List Nullable? Elements Nullable? Description
ivar~List<Type> Yes Yes Nullable list; elements can be Type or NULL.
ivar~List<(Type)> Yes No Nullable list; elements must strictly be non-null Type.
ivar~(List<Type>) No No Non-nullable list and non-nullable elements.

2. Stacks (Stack<T> — LIFO)

ivar~Stack<Int> stack = [10, 20];
stack.push(30);         ~~ Pushes to top: [10, 20, 30]
pasteLn(stack.peek());  ~~ 30 (inspects top without removing)
pasteLn(stack.pop());   ~~ 30 (removes and returns top)
pasteLn(stack.count()); ~~ 2

3. Queues (Queue<T> — FIFO)

ivar~Queue<String> clients = ["Alice", "Bob"];
clients.push("Charlie");   ~~ Adds to back
pasteLn(clients.peek());   ~~ "Alice" (inspects front without removing)
pasteLn(clients.pop());    ~~ "Alice" (removes and returns front)
pasteLn(clients.count());  ~~ 2

4. Tables (Table)

Key-value associative maps accessed exclusively through dot notation (table.field). Reading an undefined field returns NULL:

ivar~Table hero = {
    name: "Kuroba",
    hp: 100,
    port~Int: "8080",          ~~ Field-level type coercion
    token~(String): "xyz123"   ~~ Field-level strict non-nullability
};

hero.hp -= 15;                 ~~ In-place update
hero.level = 5;                ~~ Dynamically creates field 'level'
pasteLn(hero.missingProp);     ~~ NULL (safe access)

5. Nested Member & Index Mutations

Lists and Tables can be arbitrarily nested and mutated in place across mixed [index] and .property chains, including compound operators, increment/decrement, field retyping (~Type), and root iconst protection:

ivar grid = [[".", "."], [".", "."]];
grid[1][0] = "#";              ~~ Matrix 2D cell assignment

ivar enemies = [{ hp: 30 }, { hp: 50 }];
enemies[1].hp -= 10;           ~~ Mutate Table inside List -> 40
enemies[0].hp++;               ~~ Increment nested property -> 31

ivar player = { bag: ["Sword", "Potion"] };
player.bag[0] = "Bow";         ~~ Mutate List inside Table

Functions & Native Hooks

Named Functions, Signatures & Default Parameters

Named functions declare parameters prefixed by ivar with optional type coercion (ivar~Int x), non-nullability constraints (ivar~(String) name), and default values (= expr) evaluated cleanly per call when omitted:

function calculateDamage(ivar base, ivar~Int multiplier = 1) then
    return base * multiplier;
end

pasteLn(calculateDamage(25));    ~~ 25 (uses default multiplier = 1)
pasteLn(calculateDamage(25, 2)); ~~ 50

Anonymous Lambdas (function ~) & Closures

function createMultiplier(ivar factor) then
    return function ~(ivar n) then
        return n * factor;
    end;
end

ivar triple = createMultiplier(3);
pasteLn(triple(10)); ~~ 30

Native Function Interception (Hooks)

The hook statement intercepts existing function calls (or Table methods) to inject telemetry, caching, or data validation without altering the caller interface. Inside the hook body, orig(...) invokes the original function:

function processPayment(ivar amount, ivar fee) then
    return amount + fee;
end

~~ Interception hook
hook processPayment(ivar amount, ivar fee) then
    pasteLn(~"[AUDIT] Processing payment: {amount}$ (Fee: {fee}$)");
    ivar total = orig(amount, fee);
    pasteLn(~"[AUDIT] Validation approved: Total = {total}$");
    return total;
end

ivar invoice = processPayment(250, 15);

Classes & Object-Oriented Programming

Kuroba provides declarative, ergonomic Object-Oriented Programming (OOP) structured cleanly over its underlying Table collection model. Classes support C#-style constructors, auto-bound instance methods via this, field declarations with visibility access modifiers (public, private), automatic parameterless default constructors, and runtime type checking using is.

1. Class Declaration & Fields

A class is declared with class Name then ... end. Inside the class body, you can declare instance fields using ivar or iconst, optionally prefixed with an access modifier:

  • public (Default): Accessible and mutable from both inside and outside the instance, fully inherited across subclasses. If no access modifier is specified, fields and methods are automatically public.
  • protected: Hidden from external consumers, but fully inherited and directly accessible within subclasses (via this.member).
  • private: Encapsulated member strictly restricted to the declaring class's own methods. Subclasses inherit the state in memory, but direct access in subclass methods raises a [TypeError].
  • isolated: Strictly exclusive and private to the declaring class. Subclasses do not inherit it at all (uninherited and absent from child instances).
  • exclusive: Publicly accessible on instances of the declaring class, but strictly uninherited by child classes (absent from child instances).

2. Constructors & Direct Instantiation

Constructors adopt a familiar C#-style syntax: a function whose identifier exactly matches the class name:

  • C#-Style Constructor: function Player(ivar name, ivar hp) then ... end. Invoked directly as a callable: ivar hero = Player("Kenji", 100); (no new keyword required).
  • Automatic Default Constructor: If no explicit constructor function is defined, Kuroba provides an automatic parameterless constructor (e.g. ivar pt = Point();) initializing all fields to their declared initial values.

3. Instance Methods & The this Reference

Methods declared within a class body automatically receive a reference to the active instance via this. You can inspect and mutate instance fields through this.fieldName or call internal methods with this.methodName().

Safety note: While instance properties are fully mutable via this.x = val;, reassigning the root reference itself (this = other;) is strictly forbidden and guarded as an immutable binding.

4. Complete Example: Encapsulated Hero Class

class Hero then
    ~~ Public fields (default visibility)
    ivar name = "Hero";
    ivar maxHp = 100;
    ivar hp = 100;

    ~~ Private fields (accessible only inside Hero methods)
    private ivar _energy = 50;

    ~~ C#-style constructor
    function Hero(ivar heroName, ivar heroHp) then
        this.name = heroName;
        this.maxHp = heroHp;
        this.hp = heroHp;
    end

    ~~ Public method
    function attack(ivar targetName, ivar damage) then
        if (this._energy < 10) then
            pasteLn(~"[{this.name}] Not enough energy to attack!");
            return FALSE;
        end
        this._energy -= 10;
        pasteLn(~"[{this.name}] Attacks {targetName} for {damage} dmg! (Energy left: {this._energy})");
        return TRUE;
    end

    ~~ Public getter for private state
    function getEnergy() then
        return this._energy;
    end
end

~~ Instantiation without 'new'
ivar hero = Hero("Kenji", 120);
hero.attack("Goblin", 25);
pasteLn(~"Hero energy: {hero.getEnergy()}");

~~ Private access guard check
try
    paste(hero._energy); ~~ Throws [TypeError] Cannot access private member
catch (ivar err) then
    pasteLn(~"Intercepted private violation: {err.eName}");
end

5. Type Checking with the is Operator

Kuroba's is operator seamlessly validates class instances at runtime:

  • hero is Hero → TRUE
  • hero is Table → TRUE (every class instance is fundamentally a structured Table)
  • hero is String → FALSE
class Point then
    ivar x = 0;
    ivar y = 0;
end

ivar p = Point();
pasteLn(p is Point); ~~ TRUE
pasteLn(p is Table); ~~ TRUE
pasteLn(p is List);  ~~ FALSE

6. Single Inheritance (from) & base Delegation

Classes can inherit from a parent class using the intuitive from keyword. Child classes automatically inherit all public fields and methods from the ancestor chain, while keeping their own specialized behavior:

  • Inheritance Syntax: class Child from Parent then ... end establishes an object-oriented subtyping hierarchy.
  • Parent Constructor Invocation (base(...)): Child constructors invoke the parent constructor using base(args...), initializing inherited fields with the provided values.
  • Method Overriding & Delegation (base.method(...)): A child class can override any inherited method. To invoke the parent class's original implementation, call base.methodName(...).
  • Polymorphic Type Checking: The is operator traverses the entire ancestor hierarchy: an instance evaluates to TRUE for its own class, any parent class in the chain, and Table.
class Entity then
    ivar name = "Entity";
    ivar hp = 100;

    function Entity(ivar n, ivar h) then
        this.name = n;
        this.hp = h;
    end

    function takeDamage(ivar dmg) then
        this.hp -= dmg;
        pasteLn(~"[{this.name}] took {dmg} damage. HP left: {this.hp}");
    end
end

class Player from Entity then
    ivar mana = 50;

    function Player(ivar n, ivar h, ivar m) then
        base(n, h); ~~ Invoke parent Entity constructor
        this.mana = m;
    end

    function takeDamage(ivar dmg) then
        base.takeDamage(dmg); ~~ Delegate to parent Entity implementation
        pasteLn("Shield absorbed the impact shockwave!");
    end
end

ivar hero = Player("Kenji", 200, 75);
hero.takeDamage(40);

pasteLn(hero is Player); ~~ TRUE
pasteLn(hero is Entity); ~~ TRUE (polymorphism with parent class)
pasteLn(hero is Table);  ~~ TRUE

7. Class Method Interception (hook ClassName.method)

Kuroba extends its metaprogramming system to classes: you can intercept any public method directly at the class level via hook ClassName.methodName(args...). Inside the hook body:

  • this: Always refers to the target class instance being invoked (e.g. this.name, this.hp).
  • orig(...): Exclusively invokes the original, non-intercepted method implementation on that instance.
  • Encapsulation Guard (Unhookable Privates): Methods declared as private are strictly protected against external interception; attempting to hook a private method raises a [TypeError].
class Fighter then
    ivar name = "Kenji";
    ivar hp = 100;

    function Fighter(ivar n, ivar h) then
        this.name = n;
        this.hp = h;
    end

    function takeDamage(ivar dmg) then
        this.hp -= dmg;
        return this.hp;
    end
end

~~ Intercept Fighter.takeDamage for telemetry & shielding
hook Fighter.takeDamage(ivar dmg) then
    pasteLn(~"[SHIELD] {this.name} intercepts {dmg} incoming damage!");
    ivar remaining = orig(dmg); ~~ Run original method on this instance
    pasteLn(~"[STATUS] Remaining HP: {remaining}");
    return remaining;
end

ivar f = Fighter("Kenji", 150);
f.takeDamage(45);

8. Shared Class Members (shared)

In Kuroba, static variables, constants, and utility methods belong to the class definition itself rather than individual instances, declared via the ergonomic shared keyword:

  • Grouped Block Form (shared then ... end): Group multiple static members cleanly without repeating keywords on every line. The then keyword distinguishes the block container from inline modifiers.
  • Inline Modifier Form (shared [visibility] ivar/iconst/function): Declare individual static variables, constants, or methods.
  • Strict Modifier Ordering: The shared modifier must always precede visibility (e.g. shared private ivar ...). Inverting the order (e.g. private shared) raises an intentional [SyntaxError].
  • Direct Class Access & Inheritance: Accessed directly via ClassName.member without instantiation; child classes automatically inherit parent shared members.
class Player then
    ivar hp = 100;
    ivar name = "Unknown";

    ~~ Grouped static members block
    shared then
        ivar totalCount = 0;
        iconst MAX_PARTY = 4;
        shared private ivar _serverSecret = 9876;

        function getCount() then
            return Player.totalCount;
        end
    end

    ~~ Inline static utility function
    shared function defaultName() then
        return "Novice";
    end

    function Player(ivar n) then
        this.name = n;
        Player.totalCount += 1; ~~ Mutating shared state
    end
end

~~ Direct static access without instantiation
pasteLn(Player.MAX_PARTY);     ~~ 4
pasteLn(Player.defaultName());   ~~ "Novice"

ivar p1 = Player("Kenji");
ivar p2 = Player("Aoi");
pasteLn(Player.getCount());     ~~ 2

6. Custom Property Accessors (get / set)

Kuroba supports custom property interceptors on class variables. Instead of manual getter and setter methods, you can define declarative get and set blocks that seamlessly intercept member read and write operations:

  • The value Binding: Inside both get and set, the special value variable gives direct access to the underlying raw field stored in memory, avoiding infinite recursive loops.
  • Permissive Layering: If only a get is defined, reading is intercepted while writing updates the underlying variable directly. If only a set is defined, writing is validated while reading retrieves the raw value.
  • Constant Immutability: Constants (iconst) can have a get accessor, but defining a set on an iconst raises an intentional [SyntaxError].
class Character then
    ivar hp = 100;
    iconst maxHp = 100;

    ~~ Getter interceptor on maxHp
    get maxHp then
        return value;
    end

    ~~ Setter interceptor with automatic clamping
    set hp(newVal) then
        if (newVal < 0) then
            value = 0;
        elif (newVal > this.maxHp) then
            value = this.maxHp;
        else
            value = newVal;
        end
    end

    function Character(ivar initialHp) then
        this.hp = initialHp; ~~ Runs through the setter!
    end
end

ivar hero = Character(150);
pasteLn(hero.hp); ~~ 100 (clamped by setter)

hero.hp -= 200;
pasteLn(hero.hp); ~~ 0 (clamped to zero)

Kuroba provides native, immutable enumerations for declaring fixed sets of named constants. Members default to their own string identifier for readable diagnostics and logging, or can be assigned custom explicit values (integers, strings):

Namespaces & Module Discovery

Kuroba resolves modules purely from declared AST symbols across your project, recursively scanning .krb subdirectories from the script directory in CLI (or virtual workspace tabs in the Web Playground), independent of physical file names on disk:

Hierarchy: Namespace → Module Slice (~Module) → Members

  • Main Namespace: Single entry point for applications. Strictly indivisible (cannot have ~Module) and cannot be imported by other files.
  • Direct Namespaces: Declare a self-contained namespace using namespace Utils then ... end and access its exports directly via Utils.helper().
  • Modular Slices: Split larger packages across multiple files or subfolders with namespace Game ~Combat then ... end, merging into Game.Combat.
  • Built-in Standard Libraries: Kuroba ships with two built-in packages: Std (Core modules: Math, Time, String, IO) and StdE (Standard Extended modules: Random, Json).
  • Namespace Class Modules: Declare a class directly as a module of a namespace using namespace Entities ~class Player [from SuperClass] then ... end. When imported, the class is accessible as Entities.Player() or directly as Player() with alias ~.
  • Qualified Paths & Typing: Qualified dotted paths can be used in inheritance (class Warrior from Entities.Player), instance checks (w is Entities.Player), and type annotations (ivar ~Entities.Player p = ...).
  • Symbol Discovery & Circular Guard: Kuroba indexes files by declared symbols (ignoring node_modules, .git, and the entry script) and raises an [ImportError] on circular dependencies.

Import Variations & Custom Project Files

~~ 1. Entire namespace
import Std;
pasteLn(Std.Math.PI);

~~ 2. Namespace alias
import Std alias S;
pasteLn(S.Math.PI);

~~ 3. Root exposure of entire namespace
import Std alias ~;
pasteLn(Math.PI);

~~ 4. Selective module slices
import Std ~(Math, Time, String, IO) alias ~;
pasteLn(Math.sqrt(16));

~~ 5. Standard Extended Library (StdE)
import StdE ~(Random, Json) alias ~;
Random.seed(42);
ivar roll = Random.int(1, 20);
ivar json = Json.stringify({ level: 10, ready: TRUE });

~~ 6. Importing your own project files (e.g. utils.krb & sub/combat.krb)
~~ utils.krb:      namespace Utils then function dbl(ivar n) then return n * 2; end end
~~ sub/combat.krb: namespace Game ~Combat then import Utils; function crit(ivar d) then return Utils.dbl(d); end end
import Utils;
import Game;
pasteLn(Game.Combat.crit(10)); ~~ 20

~~ 7. Namespace Class Modules & Qualified Paths
~~ entities/player.krb:
~~   namespace Entities ~class Player then
~~       ivar name = "Hero";
~~   end
import Entities ~(Player);
ivar ~Entities.Player p = Entities.Player();

class Warrior from Entities.Player then
    ivar power = 100;
end
ivar w = Warrior();
pasteLn(w is Entities.Player); ~~ TRUE

Error Diagnostics (All 8 Classes)

Kuroba provides exact line, column, and contextual diagnostics for rapid debugging:

1. SyntaxError

Grammar violations during tokenization or AST parsing:

[SyntaxError: Line 2, Col 1] Missing semicolon ';' at the end of statement.
[SyntaxError: Line 4, Col 12] Unclosed parenthesis. Missing closing ')' to match '(' at Line 4, Col 6.
[SyntaxError: Line 10, Col 5] Return statements are only allowed inside functions.

2. TypeError

Violations of runtime type compatibility or non-nullability contracts:

[TypeError] Cannot assign type 'String' to variable 'count' of type 'Int'.
[TypeError] Cannot reassign constant 'PORT'.
[TypeError] Cannot assign NULL to non-nullable variable 'user' of type '(String)'.
[TypeError] Cannot kill constant variable 'PI'.
[TypeError] Cannot hook non-function target 'score'.

3. ReferenceError

Referencing undeclared identifiers or out-of-scope hook contexts:

[ReferenceError] Variable 'unknown' is not defined.
[ReferenceError] Cannot call 'this()' outside of a hook interception.
[ReferenceError] Cannot kill undefined variable 'temp'.

4. MathError

Undefined mathematical calculations:

[MathError] Division by zero is undefined.
[MathError] Modulo by zero is undefined.

5. IndexError

Accessing out-of-bounds indices or non-integer collection lookups:

[IndexError] Index 5 out of bounds for list of length 2.
[IndexError] List index must be an integer, got 'abc'.

6. IOError

Filesystem access or permission failures in Std.IO:

[IOError] File not found: 'missing_save.dat'.
[IOError] Failed to write to file 'protected/root.dat': EACCES: permission denied.

7. ImportError

Module resolution errors, forbidden Main imports, or circular dependencies:

[ImportError] Cannot import namespace 'Main'. 'Main' is the execution root.
[ImportError] Circular import detected for namespace 'A'.
[ImportError] Unknown package or namespace 'MissingPkg'. Create a '.krb' file with 'namespace MissingPkg then ... end' or import 'Std' / 'StdE'.

8. RecursionError

Triggered when nested function calls exceed Kuroba's safe call-stack limit (512 frames). Can be trapped cleanly with try / catch:

[RecursionError] Maximum recursion depth (512) exceeded in function 'infiniteLoop'.
